emeans-dbscan: technical description

1. Purpose

This project tests fast methods that divide a large set of vectors into clusters. It uses two algorithms: e-means and DBSCAN. It also combines the two algorithms into one method.

The project answers three questions:

  1. Can the combined method find clusters of any shape?
  2. How fast is e-means on a CPU and on a GPU?
  3. Does the combined method give better results on real satellite data?

The answer to question 1 is yes, on a small synthetic dataset. Section 5 answers question 2. The answer to question 3 is no, in the one area that this project tested.

3. How the method works

Lloyd

Lloyd is the usual k-means algorithm. In each epoch, it assigns each vector to the nearest centroid. Then it moves each centroid to the mean of its vectors. Lloyd is reliable, but it is slow. This project uses Lloyd as the baseline.

e-means

e-means solves the same problem as Lloyd. The faiss library contains e-means. This project uses faiss 1.16.0.

  • e-means updates the centroids after each batch of vectors. Lloyd updates them one time in each epoch.
  • e-means uses an exponential moving average. The step becomes smaller during training.
  • e-means calculates the batch size and the first step size from n, k and the number of epochs.
  • e-means can move a centroid that has too few vectors. This action is named revival.

e-means has two limits. You must set k. Also, e-means cannot find a curved cluster, because each cluster is a convex cell.

DBSCAN

DBSCAN has two settings: eps and min_pts. A vector is a core vector if it has a minimum of min_pts vectors within the distance eps. DBSCAN connects core vectors that are within eps of each other. DBSCAN finds clusters of any shape and finds noise. But DBSCAN is slow when n is large.

The combined method

The combined method does these four steps:

  1. Run e-means with a large k. The result is k micro-clusters.
  2. Count the vectors in each micro-cluster.
  3. Run DBSCAN on the centroids. Use the count as the weight of each centroid.
  4. Give each vector the DBSCAN label of its centroid.

DBSCAN then processes only k centroids. It does not process all n vectors.

Optuna

The combined method has three settings: k, eps and min_pts. Optuna is a library that searches for good settings. In this project, Optuna keeps the settings with the highest ARI on the tuning data. The Cairo test uses the land ARI. The final score uses different data.

5. Test 2: speed on a GPU and a CPU

The data is a synthetic Gaussian mixture with d = 128. The test uses k = 4,096 and n = 1,000,000. The GPU is an NVIDIA RTX A4000. The CPU is an Intel Xeon E5-1620 v3. The error is the mean squared distance from a test vector to its nearest centroid. The method does not use the test vectors for training.

  • For e-means, the GPU is 162 times faster than the CPU.
  • For Lloyd, the GPU is 17.4 times faster than the CPU.
  • On the GPU, e-means is 33.6 times faster than Lloyd.

These times include training only. They do not include the copy of the data to the GPU.

6. Test 3: satellite data of Cairo

Data

  • The vectors are AlphaEarth Foundations embeddings for 2021. Each pixel has one vector with d = 64. Each pixel is 10 m wide.
  • The reference labels are from ESA WorldCover 2021. WorldCover is a land cover map.
  • There are two windows: the tune window and the test window. Each window has 4,096 × 4,096 pixels, which is 16,777,216 vectors.
  • The two windows do not overlap. The settings come from the tune window. The final scores come from the test window.

7. The e-means explorer

The explorer is a web application. It runs e-means in the browser on the Cairo data. It is in the folder app/.

  • User interface: ArcGIS Maps SDK for JavaScript 5.2 web components and Calcite components. The browser downloads them from the Esri content delivery network.
  • Code: JavaScript modules. There is no framework and no build step.
  • Calculation: a JavaScript port of e-means from faiss 1.16.0. It runs in a Web Worker.
  • Data: each window has a sample of 1,024 × 1,024 pixels.
  • Verification: without revival, the labels are the same as the faiss labels for the same seed. With revival, some labels can be different because of FP32 rounding.

9. Procedures

Run test 1

  1. Install uv.
  2. Open a terminal in the project folder.
  3. Run uv run --python 3.12 moons_emeans_dbscan.py.
  4. Read the scores in results.json.

Start the explorer

You must have an internet connection. You must also have approximately 3 GB of free disk space.

  1. Install uv.
  2. Open a terminal in the project folder.
  3. Download the data: uv run --python 3.12 aef_fetch.py.
  4. Prepare the data: uv run --python 3.12 app/prepare_data.py.
  5. Start the server: python3 -m http.server 8123 --bind 127.0.0.1 -d app.
  6. Open http://localhost:8123 in a browser.

Find the two solutions for k = 3

  1. Set Clusters (k) to 3.
  2. Set Seed to 1.
  3. Click Run e-means.
  4. Wait for the status "Done".
  5. Do steps 2 to 4 again for the seeds 2, 3 and 4.
  6. Compare the Cosine values in the Runs table.
  7. Keep the run with the highest Cosine value.

Stop the server

  1. Go to the terminal of the server.
  2. Press Ctrl+C.

10. Limits

  • Test 1 and test 2 use synthetic data.
  • Test 2 uses one seed. Its CPU is from 2014. Its GPU Lloyd is not optimized.
  • Test 3 uses one area and one year.
  • WorldCover is the output of a model. It is not ground truth.
  • Optuna used the reference labels. Usual clustering tasks do not have reference labels.
  • The test of k = 2 to 16 was added after the first results of test 3. The tune window selected k = 3.
  • The Mac and the Xeon selected different DBSCAN settings. The cause is not known.
  • GPU runs do not repeat exactly. For k = 199, the land ARI changed by a maximum of 0.005.
